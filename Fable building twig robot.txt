  How it's grounded

  - Each left-panel card is a real cluster from log.csv: the robot×tree anchor triangle, the robot×battery energy triangle, and the branch grounding rules
  (path_density > 0.5 → pattern, etc.).
  - Each robot component is a word with its actual quark cluster from combinations.csv: grasper = tool+animate+force, leg = support+force+animate, battery =
  energy+transducer, radar = pattern+tool+transducer, and so on.
  - As each part builds, the log lines that fire on its quarks flash in the card (e.g. the grasper highlights structure usable as leverage → tool and
  engage_anchor), then keep an amber tick — so by the end you can see which entries the finished robot covers. Goal labels (bond+support, energy+stat full)
  render in green with their own arrow.
  - Geometry is seeded per robot, so each one always grows the same recognizable twigs while keeping the organic jitter of twig_robots.html.

  Findings

  - ⚠️ (fixed during verification) Interrupting a build mid-way left a stale highlight in the abandoned card — now cleared on every new build.
  - The Energy Keeper's goal marker is an abstract green up-arrow rather than a physical part; it reads fine but is the least "grounded" visual of the set —
  easy to swap for something better if you have an idea.
  - body = container+support+animate for the Energy Keeper uses the body entry from combinations.csv; the Scout's body shows only container+support since
  its chassis isn't animate — intentional, but worth knowing it's hand-curated per robot.
